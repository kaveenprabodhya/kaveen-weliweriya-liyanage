How it is structured

What this demonstrates

  • Distributed concerns are separated: routing, discovery, configuration and domain services run as dedicated Spring Boot applications.
  • Declarative client integration: OpenFeign keeps inter-service calls explicit while allowing discovery/load-balancing infrastructure to resolve instances.
  • Resilience is represented in code/config: retry and circuit-breaker mechanisms are part of the service implementation rather than only architectural labels.
  • Observability-aware design: tracing dependencies show an understanding that debugging a distributed request requires context across processes.
  • Environment orchestration: Docker Compose captures the supporting runtime so the distributed demo can be started as a coherent environment rather than service-by-service IDE setup.

How the system is structured

Engineering depth

  • Dependency direction is deliberate: the view does not query SQLite directly; data access is confined to repository/database layers.
  • Test seams are designed in: interface-backed connection and query components allow service/controller logic to be exercised without tightly binding every test to the concrete database implementation.
  • Database bootstrapping is reproducible: committed schema and seed SQL make a fresh environment reconstructable rather than dependent on an existing local file.
  • Validation and logging are first-class: import errors, data quality checks and application events have defined paths instead of being handled ad hoc in UI callbacks.
  • Reusable architecture: the public-health domain can be replaced while preserving the controller/service/repository structure, which is the main engineering value of the project.

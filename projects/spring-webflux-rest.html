Problem

A non-blocking REST implementation using Spring WebFlux, Reactor publishers and reactive MongoDB repositories, with WebTestClient coverage of CRUD and patch behaviour.

Contribution

This demo makes the reactive execution model concrete. Controllers return Reactor types directly, repositories are reactive, and tests drive the HTTP layer with WebTestClient—including update paths that verify whether persistence should or should not occur.

Result

List endpoints expose asynchronous streams rather than blocking collections.

Design takeaway

Reactive all the way through: the HTTP layer and repository boundary both use Reactor types, preserving the non-blocking model.

How it is structured

What this demonstrates

  • Reactive all the way through: the HTTP layer and repository boundary both use Reactor types, preserving the non-blocking model.
  • Behavioural patch tests: Mockito verification confirms an unchanged patch does not trigger an unnecessary save.
  • WebFlux-native testing: WebTestClient is used instead of forcing the reactive controller through a servlet testing model.
  • Clear comparison point: alongside the Spring MVC case study, this shows understanding of when Spring’s programming model materially changes.

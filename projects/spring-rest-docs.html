Problem

A REST API documentation case study where controller tests produce verified documentation snippets that are assembled into reference material with Asciidoctor.

Contribution

This demo shows documentation as part of the verification path. Rather than maintaining an API document entirely by hand, REST Docs captures request and response behaviour from executable controller tests and feeds those snippets into the build.

Result

Documentation is driven from HTTP tests that exercise the controller surface.

Design takeaway

Docs and tests share one source of truth: the examples used in documentation come from executable HTTP tests.

How it is structured

What this demonstrates

  • Docs and tests share one source of truth: the examples used in documentation come from executable HTTP tests.
  • Build-integrated publishing: Asciidoctor and Maven configuration make documentation generation part of the normal project lifecycle.
  • Structured API model: DTOs, mappers, validation and exception handling provide a meaningful REST surface to document.
  • Useful engineering signal: the project demonstrates concern for API consumers, not only server implementation.

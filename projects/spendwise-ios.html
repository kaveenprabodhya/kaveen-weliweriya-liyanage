How the system is structured

Engineering depth

  • Feature-level MVVM: state and side effects are not embedded in SwiftUI view bodies; dedicated view models mediate user actions and API results.
  • Transport isolated behind services: budget, transaction, chart, auth and registration endpoints are grouped into domain services, keeping networking concerns away from presentation code.
  • Reusable product components: custom chart, navigation, progress and form primitives reduce screen-by-screen duplication.
  • Complete product surface: the repository covers onboarding, sign-in, budgets, transaction entry/detail, financial reporting, profile and settings rather than a single demonstration view.
  • Testing targets included: unit and UI test targets are part of the Xcode project, giving the app a defined verification surface.

Problem

An end-to-end business system for a coconut-processing exporter, covering supplier intake, production, inventory, sales, shipping and payments through a Spring Boot API and Angular client.

Contribution

The strength is the domain span. The system models a connected operational chain rather than one isolated CRUD screen: procurement enters through suppliers and field agents, production converts raw material into finished goods, inventory tracks availability, and sales/shipping/payment flows continue from the same domain model.

Result

Procurement, production, stock, customers, orders, shipping and payment records are represented in one consistent system.

How the system is structured

Engineering depth

  • Consistent API error handling: central exception handling and explicit security handlers normalise validation, authentication, authorisation and resource errors for the client.
  • Role-aware front end: administrative and agent workflows use separate navigation/layout shells rather than relying only on hiding buttons inside one screen.
  • Boundary validation: backend Bean Validation and frontend reactive forms enforce the same business expectations before data reaches persistence.
  • Pagination on growing resources: list endpoints use bounded page requests rather than returning unbounded tables to the browser.
  • API documentation and generated mappings: OpenAPI makes the HTTP surface inspectable while MapStruct removes repetitive manual DTO/entity conversion.
  • Container-ready backend: both Docker packaging and Gradle Jib configuration are present, with environment-variable based production configuration documented in the repository.

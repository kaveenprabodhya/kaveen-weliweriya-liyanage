How the system is structured

Engineering depth

  • Clear algorithm boundaries: graph traversal, filtering, co-occurrence analysis, frequent-pair mining, itemset finding, path search and recommendation each live behind focused classes.
  • Interfaces where change is expected: data sources, graphs and visualisers are abstracted so the core analysis is not coupled to a single file loader or output format.
  • Automated verification: tests cover the graph, algorithms, data processing, high-level analyser and multiple visualisation strategies, with coverage reporting documented in the repository.
  • Operational outputs: the project does not stop at console numbers; it generates interactive network views, heatmaps, static graphs and comprehensive HTML reports.
  • Complexity awareness: the README documents time/memory behaviour for co-occurrence counting, traversal, sorting and itemset growth, demonstrating algorithmic reasoning alongside implementation.
